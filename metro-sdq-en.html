Metro SDQ / M-Charging

NFC payment and top-up system for Santo Domingo Metro and cable car: Android app, admin panel, and a real-time backend.

The problem

Topping up Metro balance still depends on booths and queues, with little visibility into balance or history. The goal was a mobile flow tied to NFC while staying compatible with existing MIFARE hardware.

What I built

  • Android app: login, balance, simulated top-up, history, masked payment methods, single-use digital pass nonce, tickets, and lost-card reports.
  • Admin panel: card inventory, requests, tickets, fare settings, and action audit logs.
  • Backend: real-time WebSocket API, Supabase persistence, and sync across app, panel, and physical reader.

Architecture (short)

Android and the web panel connect to a WebSocket server on Railway. Domain state lives in Supabase/PostgreSQL. Station NFC readers report taps to the backend, which charges the fare and pushes the new balance to the app.

Security and data

  • Hashed passwords; token sessions with idle expiry.
  • Optional biometrics for sensitive actions in the app.
  • Digital pass uses a short-lived single-use nonce.
  • No full bank PAN or CVV stored (masked metadata / simulated gateway token), aligned with PCI DSS spirit and Dominican Law 172-13 on personal data.
